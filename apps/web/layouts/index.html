System Definition .archscript 
project SaaSPlatform

environment Production {
  element frontend "Customer Portal" as portal {
    tech "React"
    owner "Frontend Team"
    monitoring "Grafana"
    tags [production]
  }

  element gateway "API Gateway" as gateway {
    owner "Platform Team"
    monitoring "Grafana"
    tags [critical, production]
  }

  element service "Tenant API" as tenant_api {
    owner "Backend Team"
    monitoring "Grafana"
    tags [critical, production]
  }

  element database "Tenant Database" as tenant_db {
    owner "Database Team"
    monitoring "Grafana"
    tags [critical, production]
  }
}

relation portal -> gateway : HTTPS
relation gateway -> tenant_api : REST
relation tenant_api -> tenant_db : PostgreSQL

Why ArchScript?

More than a diagram generator.

ArchScript stores architecture knowledge in a structured, versionable and exportable format. Diagrams, documentation and reviews are generated from one source of truth.

Model architecture

Systems instead of screenshots.

Capture services, databases, gateways, domains, environments, technologies, ownership and tags in a readable DSL.

Generate artifacts

Diagrams and reports.

Generate PlantUML diagrams, SVG, PNG, Markdown documentation and branded PDF reports from the same model.

Review architecture

Make rules visible.

The rule engine detects risky dependencies and missing metadata such as owners or monitoring for critical systems.
